Pemodelan Data – Power BI

Pengenalan Power BI dan Integrasi Data dan Dashboard. Gunakan kotak pencarian di atas untuk menyaring bagian.

4. Power Query Editor

Power Query Editor = lingkungan di Power BI untuk menghubungkan, memeriksa, dan menyiapkan data sebelum digunakan lebih lanjut.

Bagian utama: Queries pane (daftar query, kiri), Data preview (tengah), Query Settings (kanan, berisi Properties & Applied Steps).

Power Query Editor vs Table View
Power Query Editor → tempat memeriksa dan menyiapkan data.
Table View → melihat data yang sudah dimuat ke Power BI.

5. Import Excel, Load vs Transform

Langkah import

  1. Home → Get Data → Excel Workbook.
  2. Pilih file (File: Pilih-File.xlsx) → Open.
  3. Di Navigator, pilih sheet/table (File: sheet Penjualan, berisi Excel Table bernama Sales).
TombolArti
LoadLangsung memuat data ke Power BI tanpa diperiksa.
Transform DataMembuka data dulu di Power Query Editor agar dapat diperiksa/disiapkan. (Yang dipilih di praktik.)

9. Menangani nilai kosong: null vs 0

  • Kolom kosong pada dataset: Customer_Name, Category, Payment_Method (dan Quantity).
  • Kolom teks Payment_Method null → diberi label "Tidak Diketahui" (Replace Values: null → Tidak Diketahui).
  • Quantity kosong → dibiarkan null.
null = nilainya tidak diketahui.
0 = diketahui bahwa jumlahnya memang nol.
Mengganti null dengan 0 pada angka bisa menyesatkan perhitungan (mis. rata-rata turun).

10. Hapus duplikat & Close & Apply

Remove Duplicates

  1. Pilih kolom Transaction_ID.
  2. Tab Home → Remove Rows → Remove Duplicates.

Bisa dicek dulu lewat Keep Rows → Keep Duplicates, atau langsung hapus lewat Remove Rows.

Memuat data

  1. Power Query Editor → Home → Close & Apply.
  2. Buka Table View → pilih tabel Penjualan untuk melihat hasil.

14. Append vs Merge

APPEND QueriesMERGE Queries
FungsiMenumpuk baris dari tabel berstruktur kolom serupaMenambah kolom dari tabel lain berdasarkan kolom kunci (ID)
ArahVertikal (ke bawah)Horizontal (ke samping)
SyaratNama & struktur kolom sama/serupaAda kolom kunci yang cocok di kedua tabel
Contoh Januari 80 + Februari 80 → 160 baris, tetap 7 kolom160 baris tetap; kolom 7 → 10 → 13
Padanan SQLUNION ALLJOIN
APPEND = menambah BARIS  |  MERGE = menambah KOLOM berdasarkan kunci

Alur: Penjualan_Januari + Penjualan_Februari —Append→ Penjualan_Gabungan —Merge (Produk via ID_Produk, Pelanggan via ID_Pelanggan)→ data lengkap 13 kolom.

15. Langkah Append Queries as New

  1. Klik query Penjualan_Januari di Query Pane.
  2. Home → Append Queries → Append Queries as New.
  3. Pilih Two tables. Table 1: Penjualan_Januari; Table 2: Penjualan_Februari.
  4. OK → rename Append1 menjadi Penjualan_Gabungan.

Append Queries biasa = hasil ditambahkan ke query yang sedang dipilih. Append Queries as New = hasil jadi query baru, query asal tetap utuh. Opsi Three or more tables untuk lebih dari dua tabel.

16. Langkah Merge & Expand

Sebelum Merge, perbaiki header tabel Produk dan Pelanggan: Home → Use First Row as Headers.

Merge dengan Produk

  1. Pilih query Penjualan_Gabungan → Home → Merge Queries → Merge Queries.
  2. Tabel atas: Penjualan_Gabungan; tabel bawah: Produk.
  3. Klik kolom ID_Produk di kedua tabel.
  4. Join kind: Left Outer (all from first, matching from second) → OK.

Expand Produk

  1. Di kolom Produk (bertipe Table) klik ikon Expand (dua panah).
  2. Nonaktifkan Select All Columns → centang Nama_Produk, Kategori, Merek.
  3. Hapus centang Use original column name as prefix → OK.
  4. Pastikan baris tetap 160. Kolom jadi 10.

Merge & Expand Pelanggan

  1. Tetap di Penjualan_Gabungan → Merge Queries → tabel bawah Pelanggan.
  2. Kunci: ID_Pelanggan; Join kind: Left Outer → OK (muncul kolom Pelanggan bertipe Table).
  3. Expand → pilih Nama_Pelanggan, Kota, Segmen, nonaktifkan prefix → OK.
  4. Hasil: 13 kolom, 160 baris.

17. Jenis join (Join kind)

Join kindHasil
Left OuterSemua baris tabel kiri (pertama) + yang cocok dari tabel kanan. Dipakai di praktik.
Right OuterSemua baris tabel kanan + yang cocok dari kiri.
Full OuterSemua baris dari kedua tabel.
InnerHanya baris yang cocok di kedua tabel.
Left AntiBaris kiri yang tidak punya pasangan di kanan.
Right AntiBaris kanan yang tidak punya pasangan di kiri.

Mengapa Left Outer? Semua baris penjualan dipertahankan; kolom referensi yang cocok ditambahkan; tidak ada transaksi terbuang hanya karena belum menemukan pasangan di tabel referensi (jika tidak cocok, kolom tambahan bernilai null).

18. Custom Column, Bulan, Bulan_Ke

Nilai_Penjualan

  1. Pilih Penjualan_Gabungan → Add Column → Custom Column.
  2. New column name: Nilai_Penjualan; formula: [Jumlah] * [Harga_Satuan].
  3. OK → cek hasil numerik dan tidak ada Error.

Contoh: Jumlah 6 × Harga_Satuan 68.000 = 408.000. Tujuan: memperoleh omzet per baris transaksi.

Bulan & Bulan_Ke

  1. Klik kolom Tanggal → Add Column → Date → Month → Name of Month → rename jadi Bulan.
  2. Klik Tanggal lagi → Add Column → Date → Month → Month → rename jadi Bulan_Ke.
  3. Cek Januari = 1, Februari = 2.
FieldKegunaan
BulanSlicer / Matrix
Bulan_KeUrutan bulan (Sort by Column)
TanggalDate Hierarchy

19. Enable Load, Close & Apply, Sort by Column

Enable Load

  1. Klik kanan Penjualan_Januari → hilangkan centang Enable Load. Ulangi untuk Penjualan_Februari, Produk, Pelanggan.
  2. Biarkan Enable Load aktif hanya pada Penjualan_Gabungan.
  3. Home → Close & Apply → Table View → pilih Penjualan_Gabungan.

Alasan: tabel sumber hanya dipakai sebagai bahan Append/Merge; tidak perlu dimuat ke model agar model ringkas. Hasil: 1 tabel aktif, 160 baris, 16 kolom.

Sort by Column (urutan bulan)

  1. Report View → klik field Bulan di Data Pane.
  2. Tab Column tools → Sort by column → pilih Bulan_Ke.

Tanpa pengaturan: urutan alfabetis (Februari sebelum Januari). Dengan Bulan_Ke: urutan kalender (Januari lalu Februari).

Perbedaan penting

  • Pie vs Donut: sama-sama proporsi bagian terhadap keseluruhan; donut berlubang di tengah.
  • Table vs Matrix: Table = daftar datar baris-kolom; Matrix = seperti pivot table, punya Rows, Columns, Values, subtotal, dan bisa expand/drill-down hierarki.
  • Top N: filter tingkat visual yang menampilkan N item teratas (atau terbawah) berdasarkan suatu nilai.
  • Drill-down: menelusuri dari level tinggi ke level rinci dalam hierarki (mis. Year → Month → Day, atau Kategori → Nama_Produk).

23. Slicer

Slicer = visual filter di kanvas sehingga pengguna dapat menyaring data tanpa membuka Filter Pane. Semua KPI dan grafik ikut merespons (interaksi antarvisual).

SlicerFieldPengaturan
1BulanStyle Dropdown / Tile; urutan Januari → Februari
2KategoriList atau Dropdown
3KotaAktifkan Search bila perlu
  • Selection: Single select atau Multi-select (atur konsisten).
  • Letakkan ketiga slicer dalam satu baris; uji kombinasi bulan + kategori + kota.
  • Hapus pilihan (clear) untuk menampilkan seluruh data.

Slicer vs Filter Pane: slicer tampil di kanvas dan mudah dipakai pembaca laporan; Filter Pane bisa diatur per visual, per halaman, atau semua halaman.
